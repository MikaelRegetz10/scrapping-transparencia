Como funciona

Nada aqui é digitado à mão: cada número desta página é o fim de uma esteira que começa no portal da entidade e termina nesta tela. São cinco etapas, e cada uma tem um lugar no repositório.

  1. Coleta

    Um módulo por portal em scrapers/ lê as páginas de transparência e devolve os links que a entidade publica — título, seção, endereço e formato do arquivo. Quando a página monta a lista por JavaScript, o scraper chama a mesma rota que ela consome, em vez de automatizar um navegador.

  2. Auditoria

    core/pipeline.py conduz o resto. O validator pergunta a cada URL se ela responde e quanto pesa; o profiler baixa o que é tabular e diz se o conteúdo pôde ser lido; o cleaner endireita as planilhas feitas para o olho, não para a máquina.

  3. Acervo

    O resultado vira Parquet em outputs/parquet/, particionado por tema, tipo de documento, ano e UF. São dois catálogos de links — um de documentos, um de planilhas — mais um conjunto por planilha aprovada, com as linhas de dentro dela. Ao lado de cada Parquet fica o _dictionary.json que descreve as colunas dele, medidas por core/dictionary_generator.py. Sai também o relatório de qualidade em Excel, uma aba por dataset.

  4. API

    api/ serve esse acervo com FastAPI e DuckDB, lendo os Parquet direto: filtros combinados, contagem por faceta, paginação, exportação em CSV, Excel ou JSON — e a conversão em planilha dos itens cuja fonte é um endpoint que só devolve JSON.

  5. Portal

    Estas páginas. HTML, CSS e JavaScript de módulo, sem etapa de build: tudo o que aparece na tela veio da API na hora em que você abriu.

Por onde começar

Documentos →

Os PDF coletados. Cada item abre o arquivo no portal de origem, e os filtros de tipo, ano e UF trabalham sobre o catálogo inteiro.

Planilhas e dados →

Os arquivos tabulares com o laudo de cada link: se respondeu, quanto pesa, se o conteúdo entrou no acervo e o que o profiler reclamou.

Visualizador →

O conteúdo de uma planilha coletada, em grade: célula selecionável, ordenação e busca sobre o conjunto todo, exportação do que está na tela.

Dicionário →

As colunas de um conjunto: tipo, quanto vem preenchido e quantos valores distintos tem. Medido no arquivo, porque as entidades publicam a planilha e não publicam o dicionário.

São três perguntas diferentes: as duas primeiras páginas dizem o que existe e se está no ar; o visualizador abre o que a última coleta guardou, sem download e sem depender de a fonte estar de pé; o dicionário não mostra dado, e sim a forma do dado — que colunas o conjunto tem e o que se pode medir nelas.

Rodando na sua máquina

São dois processos: a API lê os Parquet, o portal consome a API. Os comandos valem na raiz do projeto, com o .venv já criado.

Subir a API, na porta 8000
.venv/bin/uvicorn api.main_api:app --reload --port 8000
Servir o portal, na porta 8001
.venv/bin/python -m http.server 8001 --directory portal
Coletar de novo, alimentando o acervo
.venv/bin/python main.py

Abrir os .html direto do disco não funciona: o navegador bloqueia módulos JavaScript no esquema file://. Para apontar para outra API sem editar código, passe o endereço na URL — planilhas.html?api=https://api.exemplo.org. A documentação interativa da API fica em /docs, e os detalhes de cada página estão no README do portal.

O que o acervo ainda não faz

  • O ano é pouco confiável. Os scrapers nem sempre acham o exercício no arquivo, e os registros trazidos do histórico caem no ano corrente. Uma coleta nova corrige.
  • A UF só tem estado de verdade nas planilhas. Nos documentos tudo é DN, e está certo: os PDF catalogados são os da ABDI e do SESI nacional.
  • Cabeçalho torto na origem continua torto aqui. Acento corrompido na coleta é dado do acervo; consertá-lo é trabalho de uma coleta nova, não da tela.
  • O dicionário descreve o arquivo, não o campo. Ele diz que uma coluna é texto e que nunca se repete; não diz o que a entidade entende por ela. Esse significado não está no acervo porque não está na fonte, e a página prefere dizer isso a adivinhar.
